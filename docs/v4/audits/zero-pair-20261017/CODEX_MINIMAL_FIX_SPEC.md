## 3순위: 수량·시점·구조화 전달의 계약 검증 — 구현 확정 전 개발 시험

확인한 동작은 있으나 실제 완성쌍 오차단은 확인하지 못했다. 이 항목을 실제 병목 소실 버그라고 보고하지 마라.

1. `quantitative_targets.comparable`은 물량 비교용이다. 날짜만 있는 입력을 거부한다. 반면 최종 forecast.comparison은 수량 없이 timing gap을 반환할 수 있다.
2. 옛 `evidence_path.analyze`는 need_time/ready_time 문자열이 같아야 연구쌍을 만든다. 다른 날짜 기반의 시점 격차와 같은 비교기간 표현을 구분해야 한다.
3. `official_discovery.q3_input`의 typed `eligible` 목록은 최종 selected/eligible_pairs에 직접 사용되지 않는다. 최종 선택은 그래프 신호에 의존한다.

- 첫 작업: 기존 그래프→forecast의 날짜 경로가 실제 source-bound 입력을 받는지 개발 fixture에서 재현하고, 양쪽 경로의 의미를 명세한다. 기존 경로가 지원하는 상황이면 새 비교기를 만들지 않는다.
- 변경 후보: 수량 경로와 시점 경로를 명시적으로 분기하는 기존 adapter; typed 사건의 원문 좌표를 기존 graph 신호로 전달하는 연결 계약. 기존 supply qualification·coverage·basis·독립성 조건은 유지한다.
- 완료시험: 수량 미공개지만 동일 범위·확정 필요일/적격 가용일·독립 원문이 있는 개발 fixture에서 시점 경로 통과. 실제 원문쌍이 없으면 SYNTHETIC만 표기한다.
- 회귀시험: 늦지 않은 공급→부족 경보 없음; 공급 일부만 알려진 경우 전체 시장 공급으로 오인하지 않음; 수량 부족→기존 판정 유지; 단위/기간 불일치→수량비교 보류; 계획/예상 출하·인증 대기→가용 공급으로 승격 금지; 같은 원문 재인용→독립성 차단; 다른 고객/규격/제형/지역→차단; 기존 완화·재고·대체 근거 유지.
- 실제 입증 조건: 동일 TARGET 실제 원문으로 충분한 정보가 있는 사례가 확보되기 전에는 ‘실제 연결 개선’ 완료를 선언하지 않는다.
- 코드 필요 여부: 현재 연구 계약이 의도적으로 typed 공급을 채택하지 않는 것인지 먼저 확인. 진단/테스트만으로 끝날 수 있으며 미확인 자동 채택 기능을 선제 구현하지 않는다.
- 위험/난이도: 높음. 잘못 연결하면 오탐 급증. Q3 개발 검증 안에서 수행하며 Q4/Q5·S3·LIVE 승격은 아님.
