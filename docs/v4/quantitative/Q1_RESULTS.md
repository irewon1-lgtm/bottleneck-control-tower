## 값·변경·저장 검증

원문 위치 표본66개를 source/type/status/부호/단위 그룹의 처음·마지막으로 고정해 직접 대조했고 값·위치 오류0건이었다. 이는 전체 행 정확도100%나 독립 평가가 아니다. 단위/기간의 미확인은 별도로 유지한다. 미확인·W·각주를0으로 바꾸지 않으며, USGS의 괄호 각주와 금액의 괄호 음수를 구분한다. TED 숫자는 Decimal로 읽고 다중 lot 배열은 임의로 짝짓지 않는다. 계약 시작일은 관측기간이 아니므로 기존 초안을 보존하고 검증 출력에서UNKNOWN으로 정정했다.

실제 USGS 같은 기간 개정15건 중5쌍을 두 원본 셀로 재대조했다. EIA는 다른 관측월 두 판을 기존 비교기로 대조해 상태변경54건(가동 보고16, 미검증 상태/분류변경38), 행추가/누락17건, 값/메타데이터 차이115건을 구분했다. 이를 같은 월 개정이나 적격 공급 증가로 처리하지 않는다.

기존 Ledger의8개 테이블을 백업→gzip→새 프로세스 복원→SHA/논리 내용 대조했다. 실제 Q1 DB를 이용한 잘못된 로컬 기대 해시의 저장 거부/정상 복구,10개 고정 파일 작업의 no-op(추가 HTTP/모델0), 실제 DB 복사본의 미커밋 상태에서 exit17→롤백을 검증했다. 이것은 비공개 Git 원격 CAS/복원 PASS가 아니다. 원격 저장은 GitHub 인증 차단으로 미실행이다.

변경 영향 시험은 Q1 29개+기존 UI 조회1개 총30 PASS(2.30초). 기존 전체 회귀·230원문 QA·GitHub CI는 이번에 실행하지 않았다. UI 디자인·운영 데이터·기존 판독/모델·Secret은 변경하지 않았다.

대표 실제 값은 `quality-evidence.json.checks`와 두 판 개정 예시에 숫자·단위·기간·근거 위치/해시를 기록했다. 원문·Q1 DB·전체 검증용 출력은 승인된 로컬 연구 경로 `var/v4/quantitative/q1/`에만 두었고 공개 Git에 추가하지 않는다. 원격 비공개 보관은 추가 검증이 필요하며 이전 CPU/원문3건 보관을 재설정하지 않았다.

GitHub 연결 복구 후 최신 원격을 fetch/일반 merge로 보존하고 로컬 Q1 변경을 push·같은 SHA CI 확인한다. force push/reset을 하지 않는다. **이 문서 커밋 SHA를 CPU CODE_SHA로 넣지 않는다.** 토큰·64자 암호·모델을 다시 만들지 않는다. 출처별 next cursor는 기존 PROGRESS.json.quantitative_plan에 있다. 고정 범위의1210개 계약 거래 이력 및 출처별 공백을 이어 처리한다. Q2·새 정기 작업·후보 승격은 시작하지 않았다.


현재 원문 파일 복구 도구는 고정 해시와 다르면 새 버전으로 별도 보존하고 그 입력은 보류한다. 같은 잘못된 버전을 반복 다운로드하지 않는다. 실제 USGS19판은 추가 HTTP0회로 재사용/no-op을 확인했다. 원문 파일은 DB 체크포인트에 포함되지 않으므로 DB 복원만으로 원문 전체가 복구된다고 주장하지 않는다.

기존 CPU 비공개 게시/복원기는 CPU 큐 형식과 고정 ref를 요구한다. Q1 캡슐을 CPU seed에 넣거나 CPU 상태를 덮어쓰지 않았다. Q1 전용 namespace/형식 어댑터와 실제 비공개 게시·복원은 미완료다. 인증 경로 복구 후에도 이 부분을 먼저 검증해야 하며 CPU CODE_SHA 변경으로 대체하지 않는다.
