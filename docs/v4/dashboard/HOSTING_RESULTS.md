## 방식과 선택 근거

기존 Python HTTP 서버는 127.0.0.1 전용이며 인증이 없다. 연결된 Sites는
Cloudflare Worker를 실행하며 기존 Python 장기 프로세스·로컬 SQLite를 그대로
운영하는 환경이 아니다. 따라서 Python 서버를 인터넷에 노출하지 않았다.

기존 `ResearchReader`로 검증된 SQLite 백업을 읽고 기존 세 화면 자산과
API 조회 결과를 하나의 의존성 없는 Worker ESM 파일에 포장했다.
새 프레임워크·AI 호출·DB migration·예약 작업을 추가하지 않았다.
네 화면, 검색·필터·페이지 이동·상세·공식 표 비교·다운로드 API 경로를 유지한다.

화면에는 고정 스냅샷, 데이터 기준 시각, 배포 자료 생성 시각을 명시한다.
새로 읽기는 동일한 저장 자료의 재조회다. 새 수집·판독·후보 생성은 실행되지 않는다.
화면에서 읽은 시각만 브라우저의 현재 시각으로 표시한다.

연결된 Sites의 비공개 호스팅을 사용했다. 별도 유료 호스팅 계약·과금 API·
추가 결제·유료 플랜 변경 0건. 향후 요금 정책·계정 제공 범위의 영구 무료를
보장하거나 별도 청구 내역을 확인했다고 주장하지 않는다.

## 보존 및 재개

GitHub 변경은 exporter와 이 보고·HTTP 결과뿐이다. 기존 dashboard.py,
dashboard_web 세 파일, 연구 백업, 운영 main, 기존 개발 브랜치, 원문,
운영 Actions, 엔진, AI 자동 판독 설정은 변경하지 않았다.

재개는 배포 URL의 모바일 화면·실제 기기 시험과 다음 세션 재접속 확인이다.
전체 작업을 재구축하거나 통과한 PC/API 시험을 반복할 필요는 없다.
데이터 갱신은 새 연구 자료를 같은 Reader로 검증·포장해 같은 비공개 Site에
배포하는 작업이며 자동 갱신으로 구현하거나 활성화하지 않았다.
